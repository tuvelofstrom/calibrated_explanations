# v1.1.0 Plan

> **Release version:** `1.1.0`
> **Development version:** `1.1.0-dev`
> **Status:** Active
> **Theme:** Minimal offline narrative semantics and core-contract consolidation

## Outcome

Accept ADR-041 as a small, deterministic presentation-neutral representation of already-computed explanation facts. Keep the existing offline template narrator and public API fully standalone. The release also implements canonical ranking (ADR-042), one-sided CPS endpoint representation, strict environment-token validation, typed call-time parameters, governance-event redaction, existing-plugin CLI validation and the planned root export deprecation. No narrative provider framework or network narrative service belongs in the scope of this release.

## Excluded

- New narrative plugin family, runtime provider registry or trust/deny mechanism for text generators.
- Provider selection and network-specific tuning on the OSS public narrative API.
- External narrative output verification, transport or dispatch-specific capability claims.
- Provider SDKs, LLMs, prompts, credentials, remote inference and network access.
- Global narrative summaries without an established non-visual semantic source.
- Changes to calibration algorithms other than the separately tracked endpoint representation.

## Dependencies and gates

- T1 precedes T2-T4; T3 and T2 supply T4. T5 must remain usable before and after T2-T4.
- T6's ADR-042 ordering is authoritative for T4 and legacy rendering where it applies.
- T7's unbounded endpoints are compatible with T4's invariant checks.
- T11 validates only the existing registered plugin types.
- Tests must establish that `to_narrative()`, `narrate()`, `to_dataframe()` and `plot(style="narrative")` retain their documented outputs, work offline and preserve numeric semantics.
- Round-trip payload regression, deterministic contract tests, CE-first API tests, numerical parity, `make capability-chain-check`, docs build and `make local-checks-pr` must pass before release.
- No new narrative runtime dependencies or reverse imports.
- Release handoff follows `release.md`; this plan does not claim unrun gates passed.
